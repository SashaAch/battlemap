## Что сделать

Всё из раздела 8.4, пункты 1..6. Уточнения главного агента (разбор плана, не решения заказчика):

- **Режимы клиента** (5.3): при загрузке клиент запрашивает `api/me`. Сервер не отвечает или ответ не от нашего сервера (GitHub Pages) → черновик без сервера, как сейчас. 401 → экран входа (и регистрации по коду). 200 → доска как сейчас (игр ещё нет, это этап 5) плюс в шапке имя пользователя, смена пароля, выход и, у администратора, администрирование. Если пароль сброшен (`must_change_password`), до смены пароля ничего другого не доступно, и сервер это же проверяет на своей стороне.
- **Сервер** `server/main.ts` на `node:http`; раздаёт `client/index.html`, `style.css`, `themes.css`, `dist/` с `Cache-Control: no-cache`; путь за пределы `client/` не отдаётся (тест на `..` и закодированные варианты). Заголовки на всех ответах: `Content-Security-Policy: default-src 'self'` (плюс `frame-ancestors 'none'`), `X-Content-Type-Options: nosniff`, `Referrer-Policy: no-referrer`. HTTPS из настроек не делать (этап 15), но при запуске по HTTP печатать предупреждение, что пароли идут открытым текстом.
- **Запросы 6.4** этого этапа: `POST /api/auth/register`, `login`, `logout`; `GET /api/me`; `POST /api/me/password`; `PUT /api/me/settings`; `GET`, `POST /api/admin/users` (создать, сбросить пароль, отключить), `POST /api/admin/invites`. Ответы и коды статусов по 6.4. Ошибки только кодами (`{ "error": "auth.invalid" }`); список кодов сервер держит в одном месте, у каждого кода текст в обоих словарях, тест это сверяет.
- **Изменяющие запросы** принимаются только с `Content-Type: application/json` (иначе 415) и с `Origin`, совпадающим со схемой и `Host` запроса (иначе 403, в том числе без `Origin`). Тело до 2 МиБ, для входа и регистрации до 4 КиБ (иначе 413), обрыв чтения на лимите, а не после.
- **Пароли**: `crypto.scrypt` асинхронно (не блокировать цикл событий), соль 16 байт, сравнение `timingSafeEqual`. Логин, имя и пароль по 6.2.
- **Сессии** по 5.10: 32 случайных байта, cookie `bm_session` с `HttpOnly`, `SameSite=Lax`, `Path=/`; в базе только SHA-256 токена; срок 30 дней с продлением при использовании; выход удаляет сессию; отключение пользователя и сброс пароля удаляют его сессии.
- **Подбор пароля**: не больше 10 неудачных входов за 15 минут на адрес и на логин отдельно, дальше 429. Время подставляется параметром, чтобы тест не ждал 15 минут. Ответ на неверный логин и неверный пароль одинаковый (не выдавать, есть ли такой логин).
- **Первый администратор**: если в базе нет пользователей, сервер при запуске печатает одноразовую ссылку настройки; токен живёт в памяти до использования или перезапуска (при перезапуске печатается новый).
- **Регистрация** (Р18): только по коду от администратора; администратор может включить открытую регистрацию. Где хранить флаг открытой регистрации, план не говорит; предлагаю `data/settings.json` рядом с портом, если найдёшь причину хранить в базе, напиши в отчёте.
- **Настройки**: `data/settings.json` создаётся при первом запуске; порт по умолчанию выбери сам и укажи в отчёте. Папка данных `data/` в текущей папке, путь можно переопределить (тесты работают во временной папке). Сервер слушает все адреса, чтобы в сети дома и в клубе можно было зайти; Windows при первом запуске спросит разрешение брандмауэра, разрешение даёт заказчик сам. Тесты слушают `127.0.0.1` на свободном порту.
- **База** `server/db.ts`: `node:sqlite`, версия схемы в `PRAGMA user_version`, миграции по порядку, каждая в транзакции; миграция 1 создаёт `users`, `sessions`, `invites` по 6.5. Весь доступ к базе только через `db.ts`.
- **Язык и тема** (5.15): вошедший пользователь хранит их в `users.settings_json` через `PUT /api/me/settings`; при входе на другом устройстве они применяются. Без входа как сейчас, в localStorage.
- **`npm run dev`** по 5.14: пересобирает клиент при изменении и перезапускает сервер (`node --watch`), только командами `node` и `npm`. Добавь скрипт `start` (`node server/main.ts`). Режим черновика без сервера (Pages) должен продолжать работать.
- Пользовательский текст (имена, логины) в интерфейсе только через `textContent`. Каждая новая строка интерфейса сразу в `ru.ts` и `en.ts`; цвета только через переменные темы.

## Правила

- TypeScript только снимаемым синтаксисом: без `enum`, `namespace`, свойств в параметрах конструктора; импорты с `.ts`, типы через `import type`. Сервер запускается `node server/main.ts` без сборки.
- Внешних пакетов во время работы нет: только встроенные модули Node.
- Каждый запрос проверяет права; на каждое правило отрицательный тест (без сессии 401, не администратор 403 и т. д.).
- Концы строк LF, пути через `path.join`. Ничего не придумывать: пути, имена, числа проверять по коду и замерами.
- Node 22.23.2 в `C:\Program Files\nodejs`, в bash: `export PATH="/c/Program Files/nodejs:$PATH"`. Временные файлы в коротком пути (`%LOCALAPPDATA%\Temp\bm-...`). Запущенные тобой в фоне серверы в конце останови. Настройки Windows и брандмауэра не трогать.
